Design the editor operating model for: $ARGUMENTS

1. Choose a structural axis with the `editor-pod-design` skill, and say
   explicitly what its failure mode is and how you will detect it.
2. Define what a great week looks like for an editor on this team.
3. Set the craft ladder in observable behaviours, and separate craft feedback
   from performance feedback.
4. Draw the review boundary with the `review-delegation-gates` skill: what
   is never delegated, what is sampled, and what the escalation route is.
5. Build the weekly cadence with the `distributed-operating-rhythm` skill if
   the team spans time zones, protecting the overlap window for decisions
   and craft feedback only.
6. Name the first three hires and the reasoning.

Before treating anyone as underperforming, check the conditions first —
briefs, approver access, references, lane fit.
